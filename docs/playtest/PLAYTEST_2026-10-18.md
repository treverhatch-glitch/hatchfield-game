# Hatchfield playtest bug list — Oct 18 2026

Build: `main` a5df0c17 (live build 64824402 + sys_17 scheduler), built and served locally, driven with one headless Chrome (Playwright, SwiftShader) plus the in-page `__hatch` playtest API (`?playtest=1`). Played from a fresh New Game as a player: title → New Game → passenger kit → sign airlines → turnarounds → terminal hall (security, placement) → save/load → every apron build tool → bulldoze → every info view → every HUD panel → an ≈8-day run at 1x, 3x and 5x → close-ups by day, night and in rain. Every item below was observed in that run or verified in code; nothing is guessed.

**Repro presets.** `R0` = clear storage → New Game → Free play · Temperate → Passenger-focused starter kit (City plot) → stamp the kit ($48k) → sign the first airline. `R1` = same with "Sandbox (unlimited money)" ticked. Main has no `?seed=` yet (sys_16 seeded RNG is still queued), so runs are default-seed; the sim-side numbers come from `__hatch` probes and repeat closely. Grid cells are `c,r` on the 32×32 plot.

**Caveat.** The box renders at about 0.6 fps under SwiftShader, so frame-rate, animation smoothness and "lag" are not judged here. Long runs advanced the sim with `__hatch.tick(0.05)`, which uses the same code path as the frame loop.

#### P0-01 · Terminal build · Hall items are charged and announced "placed" but never appear (Trever #4)
- **Severity:** P0 functional · **Size:** L · **Finding:** F44
- **What happens / repro:** R0. Terminal view → Fittings/Decor → place toilet, café, newsagent, bench, seat row, planter, art, fountain, bin. Each posts "X placed — $/day upkeep" and cash drops (−$12k for 8 items) but the render diff before/after is 22 px — nothing shows.
- **Should happen:** Every accepted item appears where clicked, or the click is refused before money is taken.
- **Likely cause:** sim.ts commitHallItem (~15916–15990): items go into legacy hall.items; on a layout-v2 hall only items that get a free socket via takeFittingSocket (terminalbuild/fittings.ts:661) become rendered fittings. The rest are paid for and invisible.
- **Proposed fix:** Make v2 layout the single source of truth: place a Fitting at the clicked tile (footprint check against layout.fittings + rooms), and refuse with a reason if it does not fit. Never charge before the fitting exists. Add a vitest: every placeHallItemAt success adds exactly one rendered fitting.
- **Screenshot / evidence:** `shots/a33_before.jpg` / `shots/a33_after.jpg`

#### P0-02 · Terminal build · Hall fills up after ~35 items: "Cell is full" everywhere in a mostly empty hall (Trever #4)

- **Should happen:** Placement capacity follows the real floor area of the hall.
